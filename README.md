# AI Messenger

Два агента Codex работают над общей задачей через Telegram. Каждый использует свою подписку ChatGPT и сам разрешает каждый запуск.
Все ходы используют GPT‑6.2 Sol с усилием Low.

## Запуск на VPS

Понадобятся Linux VPS с Docker Compose, домен, направленный на VPS, и открытые порты 80 и 443. Caddy получит HTTPS-сертификат автоматически.

1. Создай бота через [@BotFather](https://t.me/BotFather), добавь его в закрытую группу и сделай администратором. Для форума дай ему право управлять темами.
2. Скопируй проект на VPS и из его папки запусти команду, указав свой домен и ID группы.

   ```bash
   ./deploy.sh agents.example.org -1234567890
   ```

   Скрипт попросит токен бота, сохранит конфигурацию в локальном `.env` и поднимет сервисы. Если ID группы ещё нет, запусти скрипт только с доменом. Он выдаст команду `/bind` для администратора группы.

3. **В Telegram** администратор отвечает `/allow` на сообщение каждого из двух владельцев Codex. Чтобы занять слот самому, администратор может отправить `/allow` без реплая.
4. Каждый владелец открывает `/setup` в личке бота, задаёт имя своего агента и подтверждает вход на странице OpenAI. Если OpenAI просит разрешить вход по коду, включи его в настройках безопасности своего ChatGPT-аккаунта и вернись за новым кодом. `/agents` показывает, кто подключён. [Вход по коду](https://developers.openai.com/codex/auth?surface=cli#login-on-headless-devices)

У каждого агента отдельный контейнер, том с учётными данными и рабочие папки. Telegram-бот публикует результаты с выбранными именами.

### Приглашение владельца со своим Telegram-ботом

1. В группе, к которой привязан бот, администратор отвечает `/invite@имя_общего_бота` на сообщение участника и пересылает ему полученную ссылку. Она действует 24 часа, открывается только с Telegram-аккаунта этого участника и занимает слот при принятии.
2. Участник открывает ссылку, нажимает **Старт** и переходит на страницу настройки. В **Telegram-бот** он вставляет токен своего бота от BotFather, предварительно добавив бота в общую группу.
3. Там же участник задаёт имя агента и подключает Codex, подтвердив вход в OpenAI. После подключения он может отправить в группе `/new@имя_своего_бота текст задачи`. Результат публикует личный бот. Карточки и запросы на запуск по общей задаче ведёт общий бот.

Для отдельного Telegram-бота используются общий домен и один из двух существующих слотов. Токен хранится в базе в зашифрованном виде, а Codex сохраняет свой вход в томе агента. При обновлении `./deploy.sh` создаёт ключ шифрования в `.env`. При переносе на другой сервер сохрани этот файл вместе с постоянными томами. Настройки можно снова открыть через `/setup` в личке.

### VPS с общим Caddy и AppArmor

Для действующего Caddy во внешней Docker-сети `web` скопируй `deploy/compose.shared-proxy.yaml` в `compose.override.yaml` перед запуском. На хосте установи `deploy/ai-messanger-runner.apparmor` в `/etc/apparmor.d/ai-messanger-runner` и загрузи профиль командой `apparmor_parser -r /etc/apparmor.d/ai-messanger-runner`. В конфигурации Caddy проксируй домен из `PUBLIC_URL` на `ai-messanger-bot:8080`.

Этот вариант даёт первому слоту список контейнеров VPS только для чтения. При установке в `/opt/ai-messanger` скопируй оба файла `deploy/ai-messanger-inventory.*` в `/etc/systemd/system/`, выполни `systemctl daemon-reload`, затем `systemctl start ai-messanger-inventory.service` и `systemctl enable --now ai-messanger-inventory.timer`. Таймер обновляет список раз в минуту.

## Работа над задачей

- Отправь `/new` с текстом, в подписи к файлу или ответом на сообщение с заданием. Поддерживаются документ или фото до 8 МБ. В группе с темами бот откроет новую тему. В обычной группе команды отправляются ответом на сообщения карточки задачи.
- Вместо `/new` можно начать сообщение с `@имя_бота`. Чтобы взять текст или файл из сообщения, ответь на него одним упоминанием бота.
- `/new` сразу запускает агента автора, если он подключён. Нажми **Запустить** у запроса к своему агенту или ответь `/run` на сообщение задачи. После `/run` можно добавить инструкции.
- Другой человек может нажать **Попросить** или отправить `/ask`. Агент тоже может попросить чужое ревью. В обоих случаях бот тегает владельца, который решает, запускать ли свой Codex.
- Реплай владельца на вопрос агента сразу продолжает ту же сессию. Агент может приложить один готовый файл к результату.

## Проверка и обслуживание

```bash
npm ci
npm test
```

Тест поднимает настоящий бот, веб-сервис и два процесса агентов с заменами для Telegram и Codex. Он проверяет одноразовые ссылки, запрет на чужой запуск, передачу файла и продолжение сессии после ответа владельца.

```bash
docker compose ps
docker compose logs --tail=100 bot agent-one agent-two
```

Повторный `./deploy.sh` обновит сервисы с существующей конфигурацией. Том бота хранит задачи и привязку группы, тома агентов хранят сессии и вход в Codex.
